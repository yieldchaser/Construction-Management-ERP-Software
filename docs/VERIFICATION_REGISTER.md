# SiteFlow — INDEPENDENT VERIFICATION REGISTER (Tier 0)

Generated by `scratchpad/mkverif.py` from `audit/AUDIT_FIX_REGISTER.md` @ `campaign/waves`.
**This file is mine. The agent owns `audit/*`; do not merge this into it while the agent runs.**

One row per **closed** finding — the agent's `FIXED` (its own pytest) or `FIX_VERIFIED` 
(founder live-confirmed). Purpose: prove independently that the fix holds in production and 
that its test actually gates something.

Verdicts, and only these four:

- `CONFIRMED` — evidence obtained, fix holds.
- `FAKE_GATE` — the test passes against the *unfixed* tree, so it gates nothing.
- `REGRESSED` — worked before, broken now.
- `UNVERIFIED` — no evidence obtainable. Honest answer, not a failure.

- `NOT_IN_PROD` — **a fifth verdict, added during the pass.** The fix is correct in code and 
  demonstrably not in effect in production. None of the original four fit: the gate is real, 
  nothing regressed, and `UNVERIFIED` would understate a defect that has been positively 
  proven. Used only where live evidence shows the fix absent from the running system.

Anything not `CONFIRMED` gets a **new** R2 number in the agent's register. Never silently 
reopen a row.

Tier assignment:

- **Tier 1** — a test references this id. Gate integrity is checkable offline: revert the fix 
  hunk in a scratch worktree, run the test, confirm it fails at its own assertion.
- **Tier 2** — no test, but the symptom is observable live (schema change, or a frontend 
  surface). Needs Supabase / Render / browser.
- **Tier 3** — neither. `UNVERIFIED` by default until a gate is written or the risk is 
  accepted with a logged decision.

## Tier 1 result — what the 176 regression pins actually gate

Run by `scripts/verification/gatecheck.py`, which reconstructs each pin's assertion against 
the fix commit's **first parent** — the unfixed tree — and re-evaluates it there. A pin that 
holds pre-fix gates nothing.

**The structural result comes before the individual ones.** `test_regression_pins.py` is 1037 
lines and 176 tests. It imports `pathlib` and nothing else. 174 of the 176 read a source file 
as text and assert a substring is present or absent; one scans the filesystem for stock 
photos; exactly one (`test_pin_R2_129_statutory_due_date_derivation`) imports application code 
and calls it. There is no `TestClient` in the file and no HTTP request.

So even a pin that passes this check proves only that **the edit is still textually present**. 
It cannot show the code runs, is reached, or is correct. That is why every row below is 
`UNVERIFIED` rather than `CONFIRMED`: passing gate integrity is necessary, not sufficient, and 
behavioural evidence has to come from Tier 2.
